# 🏠 아파트 매매 예측 및 매물 추천 서비스

서울시 아파트 실거래가 및 주변 환경 데이터를 활용해 아파트 매매가격을 예측하고, 조건에 맞는 매물과 주변 편의시설 정보를 제공하는 웹 서비스입니다.

2023년 에이콘 아카데미 팀 프로젝트로 진행했으며, **Django 백엔드와 Kakao Map API 연동을 담당하여 데이터 분석 및 예측 결과를 웹 서비스 기능으로 연결했습니다.**

> **프로젝트 기간:** 2023.05.19 ~ 2023.06.23  
> **팀 구성:** 5명  
> **개발 형태:** 팀 프로젝트  
> **현재 상태:** 과거 구현 기록 및 포트폴리오 보존 목적

---

## 1. 프로젝트 개요

### 프로젝트 배경

기존 부동산 매물 검색을 넘어, 아파트 매매가격 예측과 주변 환경 정보를 함께 제공하여 사용자가 매물을 탐색하는 데 도움을 주는 서비스를 기획했습니다.

서울시 아파트 실거래가와 주변 환경 데이터를 활용해 가격 예측 기능을 구성하고, 지도에서 매물 위치와 주변 편의시설을 확인할 수 있도록 구현했습니다.

### 주요 기능

- **매매가격 예측:** 지역과 면적 조건에 따른 예상 매매가격 조회
- **조건별 매물 검색:** 지역 및 면적 조건에 맞는 매물 목록 제공
- **지도 기반 매물 조회:** 매물의 위치와 상세 정보 확인
- **주변 편의시설 조회:** 체육시설, 스타벅스, 백화점·대형마트 정보 제공
- **지역 통계 시각화:** CCTV, 가로등, 범죄 관련 데이터 및 연도별 평균 매매가격 조회

## 4. 서비스 처리 흐름

### 매매가격 예측

```text
사용자 입력
(지역 / 법정동 / 면적)
        ↓
Django Backend
        ↓
지역 및 면적 조건에 따른
데이터 조회·필터링
        ↓
모델 입력 데이터 구성
        ↓
학습된 모델을 통한 예측
        ↓
예측 결과 후처리
        ↓
JSON 형태로 결과 반환
```

### 지도 기반 매물 및 주변 시설 조회

```text
매물 조회 조건
      ↓
Django Backend
      ↓
매물 데이터 필터링
      ↓
매물 정보 및 좌표 반환
      ↓
Kakao Map 기반 화면 표시
      ↓
매물 선택 및 주변 시설 정보 확인
```

## 5. 주요 구현 내용

### 5.1 매매가격 예측 API

사용자가 선택한 지역과 면적을 기준으로 매물 데이터를 필터링하고, 예측 모델에 전달할 입력 데이터를 구성했습니다. 이후 모델의 예측 결과를 후처리하여 사용자에게 예상 가격을 반환하도록 구현했습니다.

당시 모델의 종속변수에 `log1p` 변환을 적용했다는 발표 자료를 바탕으로, 백엔드에서는 예측 결과에 `expm1`을 적용하는 처리가 포함되어 있습니다.

```python
y_pred = model.predict(temp_data)
y_pred = np.expm1(y_pred)
```

예측 결과를 서비스에서 사용할 가격 정보로 가공한 뒤 JSON 응답으로 반환하도록 구성했습니다.

**구현 경험**
- 사용자 입력과 모델 입력 데이터 사이의 변환
- Pandas를 이용한 데이터 필터링 및 가공
- 학습 모델과 Django 백엔드의 연동
- 예측 결과 후처리 및 API 응답 구성

### 5.2 조건별 매물 조회

사용자가 선택한 자치구, 법정동, 면적을 기준으로 매물 데이터를 필터링하고, 조건에 맞는 매물의 정보를 반환하도록 구현했습니다.

```python
df = df[df['지역구'] == gu]
df = df[df['동명'] == dong]

df_data = df[
    (df['spc2'] >= min_width) &
    (df['spc2'] <= max_width)
]
```

필터링된 매물에서 아파트명, 가격, 주소, 면적 및 좌표 정보를 추출해 프론트엔드에서 사용할 수 있는 JSON 데이터로 구성했습니다.

**구현 경험**
- 사용자 검색 조건에 따른 데이터 필터링
- Pandas DataFrame 기반 데이터 처리
- 지도 화면에 필요한 매물 속성 구성
- 백엔드와 프론트엔드 사이의 데이터 전달

### 5.3 지도 및 주변 편의시설 데이터 처리

매물의 위치 정보를 지도에서 활용할 수 있도록 위도와 경도를 포함한 데이터를 구성했습니다.

또한 매물 데이터에 저장된 주변 시설 정보를 바탕으로 체육시설, 스타벅스, 백화점·대형마트의 이름, 주소 및 좌표 정보를 추출하도록 구현했습니다.

이를 통해 사용자가 매물 정보뿐 아니라 주변 환경도 함께 확인할 수 있도록 서비스 기능을 구성했습니다.

### 5.4 지역별 통계 데이터 제공

자치구를 기준으로 CCTV, 가로등, 범죄 관련 데이터와 연도별 평균 아파트 매매가격 데이터를 조회하고, 웹 페이지에서 사용할 수 있도록 가공했습니다.

## 6. 팀 프로젝트의 데이터 분석 및 모델링

발표 자료에 기록된 팀 프로젝트의 데이터 분석 및 모델링 과정은 다음과 같습니다.

### 데이터 수집 및 전처리

- 2018~2022년 서울시 아파트 매매 데이터 활용
- 발표 자료 기준 약 266만 건 규모의 데이터 기록
- 이상치 제거
- 종속변수에 `log1p` 변환 적용
- `MinMaxScaler`를 이용한 수치형 데이터 정규화
- 범주형 변수 라벨링
- 변수 간 상관관계 분석

주요 변수에는 계약일, 자치구명, 법정동명, 건물면적, 한강공원 최소거리, 소비자물가지수, 주택매매가격지수, 금리 및 물건금액 등이 포함됐습니다.

### 모델 비교

발표 자료에서는 다음 모델을 비교했습니다.

- XGBoostRegressor
- RandomForestRegressor
- LSTM

발표 당시 RandomForestRegressor의 기존 파라미터와 GridSearchCV 적용 결과를 비교했으며, 각각 약 6.35%, 6.34%의 오차율이 기록되어 있습니다.

※ 위 내용은 팀의 발표 자료에 기록된 결과입니다. 현재 학습 코드와 평가 환경을 확인할 수 없어 평가 지표의 정확한 산출 방식이나 결과를 독립적으로 재검증하지는 못했습니다. 모델 학습과 성능 비교를 본인의 직접 담당 업무로 기재하지 않습니다.

## 8. 프로젝트 회고

### 당시 구현 방식

당시에는 기능 구현과 서비스 완성에 집중하면서 Django View에서 요청 처리, 데이터 로딩, 데이터 가공, 모델 호출 및 응답 생성 등을 함께 처리했습니다.

### 현재 관점에서 확인한 개선점

과거 코드를 다시 살펴보며 다음과 같은 개선점을 확인했습니다.

- 요청 처리와 비즈니스 로직 분리
- 데이터 접근 및 전처리 로직 분리
- 데이터와 모델의 반복 로딩 개선
- 사용자 입력값 검증 및 예외 처리 강화
- 하드코딩된 데이터와 설정값 관리 개선
- 로깅을 통한 실행 상태 및 오류 추적

현재 동일한 기능을 구현한다면 각 기능의 책임을 분리하고, 데이터 처리 및 모델 연동을 독립적으로 관리할 수 있도록 구조를 개선하고자 합니다.

이 프로젝트는 당시의 구현 경험을 돌아보고, 이후 개발 과정에서 유지보수성과 책임 분리를 고려하는 계기가 된 프로젝트입니다.

## 9. 현재 프로젝트 상태 및 실행 안내

본 프로젝트는 2023년에 진행한 팀 프로젝트로, 현재 원본 서비스의 완전한 재현을 목표로 하지는 않습니다.

- **지도 화면:** 당시 사용한 Kakao Map API 연동 부분이 현재 환경에서 정상적으로 표시되지 않습니다.
- **머신러닝 모델:** 당시 사용한 학습 모델 파일은 현재 저장소에 포함하지 않습니다.
- **학습 코드 및 데이터:** 일부 파일이 보존되어 있지 않아 전체 학습 과정을 재현할 수 없습니다.
- **소스 코드:** 당시 담당했던 Django 백엔드 구현을 중심으로 보존합니다.
- **시각 자료:** 발표 자료에 남아 있는 화면을 참고 자료로 제공합니다.

따라서 이 저장소는 실행 가능한 최신 서비스가 아니라 **당시 구현한 백엔드 코드와 프로젝트 결과, 개발 경험을 확인하기 위한 포트폴리오 아카이브**입니다.
